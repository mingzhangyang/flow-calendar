# 交接：把 assets/art 的青绿素材接入河流世界

先读 `CLAUDE.md`（工作方式、架构、青绿配色、按需重绘的约定都在里面），再读 `src/worlds/river/` 下的 `index.ts`、`scenery.ts`、`look.ts`。

## 任务

用 `assets/art/` 里的素材替换河流世界里**代码画的**景物，画风已定为绢本青绿山水（《千里江山图》）。一次只做一件事，按下面的顺序，每做完一项都出一个能试用的版本，停下来等确认：

1. **远山和雪山**：`range-far/mid/near.png` 换掉 `scenery.ts` 里 `makeRidge` 画的三层远山；`peak-1.png`（或 `peak-2.png`，让用户挑）换掉 `drawSnowPeak`。雪山居中、正对河流消失的地方，位置和大小大致沿用现在的（峰高约屏高 14.5%，底边落在地平线 `HZ`）。
2. **云**：`cloud-1/2.png` 换掉 `drawClouds`，保留“随视角时间缓缓飘”的逻辑。
3. **岸上景物**：树、草、牛羊换成精灵图，保留现在“每半小时一格、钉在时间轴上、由时间段决定样子”的摆放逻辑（`drawBanks`），只换画法：按透视缩放（`scale(z)`），底边中点对准地面点。
4. **点景**：`hut / bridge / boat / stream` 先不急着用，等用户决定“日程和风景如何呼应”后再接。

## 素材的现状（已检查）

- 全是 **RGB、没有透明通道** 的 PNG，底色是均匀的浅绢色（约 `#E8DCC0`）。
- `peak-*` 和 `range-*` 的**底部是白色的雾**，不是绢色；雪山的**积雪也是白色**。所以不能简单地“把白色抠掉”，否则雪会变透明。
- 尺寸：远山 4096×768，雪山 2048×1024，树/桥/舟/屋/溪 1024²，草/牛/羊 512²，云 1536×512。合计约 21 MB。

## 处理建议

- **预处理放到构建前做，不要在浏览器里实时抠图**：写一个 Node 脚本（如 `scripts/prepare-art.mjs`，可以用 `sharp`），从 `assets/art/` 生成 `public/art/*.webp`（或放进 `src/` 由 Vite 引入）：
  - 抠背景：按与绢色 `#E8DCC0` 的色差算透明度（边缘柔和过渡），**从图片四边做泛洪/连通区域**，只抠和外边相连的底色，主体内部的白雪不动。
  - 远山和雪山底部的白雾：改成按高度的透明渐变（越往下越透明），让山脚自然融进代码画的地平线雾里。
  - 缩小尺寸：按屏幕实际用到的最大像素（考虑 2 倍像素密度）缩小，转 WebP。目标是全部素材加起来 **2 MB 以内**。
  - 原图保留在 `assets/art/` 不动。
- **单文件试用版**：`npm run build:single` 会把图片内联成 data URI，页面总大小必须在 16 MB 以内（越小越好）。确认 `vite-plugin-singlefile` 会内联这些图片。
- **着色**：素材已经带颜色，不要再整体染色。早晚和夜里用与 `look.ts` 里 `pigment()` 一致的效果处理：
  - 绘制后在同一区域用 `globalCompositeOperation = 'multiply'` 叠一层光色（白天接近白色、黄昏偏暖、夜里约 `[0.36, 0.4, 0.5]` 倍的偏青暗色），或者预先生成白天/夜里两版再按 `daylight` 混合。选简单、帧率稳的做法。
  - 远处的东西要淡进雾里（和 `pigment(..., mist)` 一样的意思）。
- **性能**：图片解码一次、缓存好；拖动时逐帧画，手机上要流畅。不要每帧 `createPattern` 或重复解码。静止时不增加重画次数（看 `__flow.redraws`）。
- **图片还没加载好时**，先用现在代码画的版本兜底，加载完成后 `requestRender()` 一次。
